# Catena

Catena 是 Windows 优先的多窗格文件工作台。常用目录可以固定在各自窗格，搜索结果能定位到指定窗格，工作区在重新启动后恢复。

当前开发版包含基础浏览、工作区保存、统一查找、文件预览，以及可配置 OpenAI 兼容模型的 AI 查找与文件整理对话。界面使用 Windows 文件类型图标，支持跟随系统、浅色、深色和蓝雾背景。

## 已实现

- 单窗格、上下双窗格、左右双窗格与四窗格，左右、上下边界及预览宽度实时拖动，尺寸随工作区保存，隐藏窗格状态保留。
- 可点击路径面包屑、Ctrl+L 地址输入、前进后退、上级目录、刷新，以及默认应用打开文件。
- 每个窗格独立的过滤和排序，支持多选、固定目录与一键返回。
- SQLite 工作区自动保存、启动恢复、另存、切换、重命名和删除。
- 顶部输入关键词或路径，先选择范围和文件名 / AI 描述方式，Enter 后在独立窗口展示结果。默认递归搜索当前工作区所有可见窗格的目录；窗格搜索图标切换到该窗格范围。
- 索引不可用时，可明确改用当前文件夹递归查找；支持取消、200 项上限和跳过错误汇总，不跟随 junction 或符号链接。
- 文件搜索结果定位到父目录并选中；目录结果直接进入目标窗格。
- 复制路径、打开 PowerShell、在资源管理器中显示。右键使用应用内常用操作菜单，可复制文件或路径、粘贴文件、重命名、删除及查看属性；菜单弹出不加载 Windows Shell 扩展。
- Everything Unicode IPC 直接查询，无需每次启动 ES 或写入临时结果文件，支持并发查询、取消和工作区多目录合并。结果一次性更新，列表保持虚拟化。
- AI 将自然语言转换为文件名、扩展名、修改日期与大小条件，再通过 Everything 查找真实文件。
- 设置窗口支持 Base URL、模型 ID、API Key、超时与连接测试。密钥通过 Windows 当前用户 DPAPI 加密保存。
- Windows 系统文件夹与文件类型图标，后台读取并按类型缓存。
- 图片、文本/代码和 PDF 分页预览。PowerPoint 与 Word 优先使用本机预览处理程序；不可用时，PPTX 提供有明确限制提示的兼容分页预览，DOCX 可展示正文。
- 每个窗格独立的目录树与系统文件夹选择器，常用位置、近期访问和磁盘入口可直接定位。
- OneDrive 自动加入常用位置，后台缓存目录结构及文件元数据，提供文件类型分布、目录层级和数量统计。

## 运行

本地迭代可直接运行 `artifacts/win-x64/Catena.App.exe`，每次完成开发和验证后更新此固定位置，无需重新安装。运行时需保留同目录的依赖文件。

普通用户使用 `artifacts/installer/Catena-0.6.2-win-x64-Setup.exe` 安装即可。安装包包含 .NET 运行时、ES 和官方 Everything 1.4.1.1032 安装组件，安装时无需联网。缺少 Everything 时自动安装并启用索引服务；已有安装则复用。Windows 会在安装阶段请求管理员授权，日常使用 Catena 无需提升权限。

首次查找会自动启动 Everything 后台客户端。首次建立索引需要一些时间。实例名默认留空即可，高级设置可指定自定义实例。ES 仅保留作诊断和基准对照，日常搜索直接使用 IPC。便携目录也附带安装组件，可在设置中点击「安装搜索组件」。

以下命令供开发使用。

需要 Windows x64 和 .NET SDK 10.0.401。仓库若已有 `.tools/dotnet`，脚本会优先使用它。发布包自带运行时。

在项目根目录执行。

```powershell
./scripts/dev.ps1 restore
./scripts/setup-everything.ps1
./scripts/dev.ps1 build
./scripts/dev.ps1 test
./scripts/dev.ps1 run
```

生成自包含 Windows 包。

```powershell
./scripts/dev.ps1 publish
```

输出在 `artifacts/win-x64/Catena.App.exe`。复制整个 `win-x64` 文件夹使用，不要只复制 exe。

生成离线安装包需准备 Inno Setup 6.7+，然后运行 `./scripts/package.ps1`。编译器可放在 `.tools/innosetup`，也可通过 `-Compiler` 指定。脚本自动下载并校验依赖、发布应用和编译安装包。详见 [打包说明](docs/installation.md)。

首次运行显示双窗格。单击某个窗格后，应用内快捷键作用于该窗格。Ctrl+K 聚焦顶部输入框，右侧筛选图标选择搜索范围与方式，Enter 展示结果。点击窗格标题右侧的搜索图标可限定到该窗格。筛选与目录图标放在路径栏右侧；筛选只影响当前列表。

拖动窗格间边界调整大小，悬停时显示方向光标并高亮边界；双击可均分左右或上下窗格。预览侧栏也可以拖动，双击恢复默认宽度。调整结果随工作区保存。窗格保留最低宽度和高度，避免拖动后完全消失。

工作区下拉框右键可打开管理、常用位置或切换单窗格。右上角三段按钮依次为四窗格、上下双窗格和左右双窗格。复制路径、终端、刷新和 AI 对话收在窗格标题右侧的「⋯」中。快捷键通过悬停提示查看。

## Everything 与 AI 设置

1. 使用 Catena 安装包完成安装，搜索组件会自动准备。已有 Everything 时保留其索引范围和配置。
2. 通常可直接开始查找。需要诊断时打开「设置」并点击「检查搜索组件」；便携版缺少组件时点击「安装搜索组件」。
3. 顶部输入文件名关键词。多个空格分隔的词要求同时命中，不接受 Everything 高级语法。可选工作区、当前窗格或此电脑，目录范围均包含子目录；结果上限可在常规设置中调整为 50–1000 项。
4. 配置 AI 的 Base URL（如服务商提供的 `https://host/v1`）、准确的模型 ID 和 API Key，点击「测试模型连接」，然后保存。也可填写完整的 `/chat/completions` 地址。本机服务支持 `http://localhost:端口/v1`，无鉴权时 Key 可留空。
5. 在顶部搜索选项中选择「AI 描述」，输入例如「找上个月修改的预算 Excel 表」后按 Enter。结果窗口显示解析后的条件，双击结果定位到发起搜索的窗格。AI 仅在提交时调用。

接口采用 OpenAI 兼容的 [Chat Completions 格式](https://developers.openai.com/api/reference/resources/chat)。模型需要能返回简短 JSON；没有硬编码服务商或模型。AI 只在明确提交时请求，连接测试也会发送一条示例描述。AI 查找发送输入描述、解析规则与当天日期，不发送本地列表或正文。AI 对话的发送范围见下文。

这一版 AI 辅助匹配文件名和元数据，尚不理解文档正文。普通查找不调用模型。Everything 不可用时，全电脑查找会显示原因和「改查当前文件夹」按钮。已选择当前文件夹时，明确提交普通查询会退回该目录的递归查找，并标明实际使用的方式；输入过程中不会反复扫描目录。

## AI 对话

从窗格标题右侧的「⋯」打开 AI 对话，可询问文件夹组织和归档建议。连接使用设置里保存的模型，点击发送或按 Enter 请求，Shift+Enter 换行。支持流式回复、逐字显示、停止生成与复制。对话仅保存在本次应用会话中，切换该窗格目录后重新打开会开始新对话。

「目录概况」默认开启，发送时附上打开对话时的路径、最多 120 个可见条目的元数据，以及该位置已有的结构统计。可关闭此开关。不会自动读取目录中文件正文，也不会按建议移动或删除文件。

Ctrl+V 可粘贴资源管理器中的文件、截图或文字，也可用「＋」选择附件。每次最多 4 个附件，单文件不超过 8 MiB。文本和 DOCX 提取前 16K 字符，图片压缩到最长边 1536 像素后发送，PDF 使用接口文件部分；模型须支持相应附件格式。目录、在线文件和不支持的格式显示「仅属性」，不会为添加附件下载 OneDrive 在线正文。附件在发送前可移除，接口错误保留已收到的回复。

接口流格式依据 [OpenAI 流式响应说明](https://developers.openai.com/api/docs/guides/streaming-responses)，图片部分依据 [图像输入说明](https://developers.openai.com/api/docs/guides/images-vision)。回复正文支持标题、段落与代码块，不加载模型回复中的远程图片或网页脚本。

## 文件预览

单击文件列表中的条目，右侧显示内容与文件信息。顶部「预览」或 Alt+P 可以收起侧栏，为多窗格留出更多空间。

- 图片支持 PNG、JPEG、BMP、WebP、GIF 和 ICO，显示静态图像。文件读取上限 16 MiB，拒绝超过 5000 万像素的图片，预览长边最多 1024 像素。
- 文本和代码读取前 64K 字符，支持 UTF-8 与带 BOM 的 Unicode 文本；不支持的编码提示使用默认应用打开。
- Word 优先使用系统注册的进程外预览处理程序，调用在独立 STA 线程执行。未注册处理程序时，DOCX 提取最多 64K 正文；处理程序失败时显示提示。
- PDF 由 Windows 自带引擎逐页渲染，不依赖 Acrobat 注册项；PPTX / PPTM 直接解析 Open XML，预览文字、普通形状和嵌入图片并支持翻页。PPTX 预览不完整还原母版、组合变换、图表或动画，复杂版式需在原应用中查看。两类文件读取上限 128 MiB。
- 旧版 PPT、Word、Excel 等格式使用系统注册的预览处理程序，需相应软件提供支持。文件夹只显示信息，不递归计算大小。

预览在本机读取，不上传给模型。快速切换选择会取消旧预览，图片解码与图标提取在后台执行。当前图标按 Windows 文件类型关联获取，不提取每个文件的缩略图或自定义可执行文件图标。

## 目录树、近期记录与结构缓存

每个窗格点击路径栏右侧的目录图标展开独立目录树，单击目录设置该窗格路径。地址栏旁的「…」打开系统文件夹选择器。目录树和文件列表的边界可以拖动，显隐与宽度随工作区保存。

目录树包含常用、最近、当前和此电脑。默认发现当前用户的 OneDrive（包含个人与企业环境变量及用户目录下的 OneDrive），首次启动加入常用位置。树上的「＋」将当前文件夹加入常用并建立缓存；工作区右键菜单中的「常用位置与近期记录」可以添加、移除、更新或取消缓存，并查看结构统计。

近期记录包含在 Catena 中成功访问的目录，以及通过 Catena 打开的文件，跨窗格共享。启动恢复、刷新和失败导航不计作访问。最多保留 300 个位置、90 天记录，界面显示最近 30 项；可在「位置」中清除。不会读取其他应用的使用记录。

缓存先保存文件夹层级、名称、类型、大小和修改时间，画像展示文件与文件夹数量、类型分布、主要分支、层级和最近修改时间。目录树先读缓存；超过 5 分钟的目录在展开时更新，也可手动刷新。完整画像在启动时超过 24 小时会后台更新，也可从「位置」手动更新。当前没有文件系统实时监听，画像有明确的更新时间。

单轮完整扫描默认最多 20 万条目、64 层目录、120 秒检查预算，后台串行执行，可取消。上限或访问失败会标为部分结果；局部扫描保留已有缓存，目录离线也保留旧结构。单个目录树节点最多显示 2,000 个子目录，达到上限会提示。底层文件系统调用的阻塞时间仍受磁盘和网络影响。

结构扫描不读取正文，不发送给 AI。Windows 云目录可遍历，目录联接、符号链接和未知重解析点不自动深入；自动预览遇到在线文件标记时不读取正文。相关属性依据见 [Microsoft 重解析标记说明](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-point-tags)。当前画像属于文件结构统计，正文语义分析仍待后续实现。

搜索基准报告保存在 `artifacts/screenshots/everything-benchmark.txt`。同一隔离文件列表索引分别测量直接 IPC 与 ES 路径，各执行 30 次热查询；统计包含查询与解析，不含界面绘制和 AI 网络耗时。合成索引结果不能代替实际磁盘索引的完整体验。

## 外观与设置

设置分为常规、外观、Everything、AI 功能、关于、帮助六类。外观可选择跟随系统、浅色或深色，并设置蓝雾背景及浓度。背景使用单张缓存位图，不持续执行模糊或动画。Ctrl+滚轮缩放当前窗格列表，范围 75%–200%，随工作区保存。

发布目录排除调试符号，图形库的原始符号仍留在开发构建目录。没有引入浏览器内核或额外 PDF 渲染引擎。

## 数据保存

默认数据库在 `%LOCALAPPDATA%/Catena/workspaces.db`。可设置 `CATENA_DATA_DIR` 指向其他目录，测试数据与日常工作区可据此分开。

常用位置、近期记录和目录结构保存在同目录的 `navigation.db`，与工作区数据库分开。移除常用位置会移除它的结构缓存，不删除原文件。按需展开缓存最多保留 100 个目录；常用位置最多 20 个。缓存库异常时保留原库，目录列表仍可浏览。

模型及搜索配置保存在同目录的 `settings.json`。Key 输入框留空会保留已有密钥，勾选清除才会删除。更换接口主机需填写新密钥或明确清除旧密钥。加密密钥不能直接迁移到其他 Windows 用户。配置文件损坏时保留原文件并禁用保存。

工作区按约 700 ms 防抖保存，正常退出会再提交一次。SQLite 事务一起保存工作区与最后活动 ID。搜索输入和结果不入库。

路径离线或已删除时保留原路径，显示错误并允许刷新。数据库损坏或版本不兼容时进入临时会话，禁用工作区写入并保留原文件。恢复时先退出应用、备份原库，再用自己的有效备份替换；当前尚无图形化恢复工具。

## 工程结构

| 工程 | 职责 |
|---|---|
| Catena.Contracts | 位置、文件条目、文件 Provider、搜索与系统动作契约 |
| Catena.Core | 独立窗格导航、历史、工作区数据及存储接口 |
| Catena.Storage.Local | 本地目录分批读取、路径规则、限定目录搜索 |
| Catena.Search.Everything | ES 本地 IPC 查询、受限搜索条件编译与 EFU 结果解析 |
| Catena.AI | OpenAI 兼容接口、自然语言条件解析、响应校验与取消 |
| Catena.Persistence | SQLite 工作区事务、JSON 设置原子写入、版本检查 |
| Catena.Platform.Windows | 系统动作、DPAPI 密钥保护、Everything 自动发现与后台启动 |
| Catena.App | Avalonia 界面、MVVM 命令、依赖注入与自动保存 |
| Catena.Tests | 路径、竞态、搜索、持久化及关键界面流程测试 |

Core 不引用 Avalonia、SQLite 或 Windows API。ViewModel 通过接口调用具体服务。范围递归搜索实现 `ISearchProvider`，索引搜索实现 `IIndexedSearchProvider`，远程目录实现 `ILocationProvider`；有真实扩展需求后再增加插件宿主。

SDK 与直接依赖版本固定，传递依赖记录在各工程的 `packages.lock.json`。CI 使用锁定模式恢复，并在 Windows 上编译和运行测试。SQLite 原生依赖显式使用 3.x bundle，避开旧版 2.1.11 的安全告警。

## 当前限制与后续顺序

1. Everything 已通过 ES 接入真实索引；直接 SDK 适配、自建索引、正文语义检索仍待开发。搜索速度受索引规模、查询条件与 ES 启动开销影响。
2. 目录变更监听、滚动位置恢复、窗口位置恢复和结构化日志仍待补充。当前通过 F5 刷新。
3. 虚拟化列表和批量读取已实现。10 万条目、慢盘、真实 UNC 服务和断盘测试尚未完成；没有宣称达到需求文档的性能目标。
4. SQLite 当前 schema 为 1，支持新建与版本检查。后续改变 schema 时需加入备份及迁移流程。
5. 文件复制、移动、删除、拖放和插件均留到后续阶段。应用目前不修改被浏览的文件。
6. Linux/macOS 未验收。系统动作以 Windows 为首个实现。

原始需求保存在 [需求文档](docs/requirements-v1.md)，本次实现边界与验收记录见 [开发进展](docs/development.md)。原文中的性能数据均为目标。
