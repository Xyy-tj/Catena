# Catena：产品需求与技术开发路径

版本：v1.0 · 日期：2026-09-28 · 项目名暂定，可替换

## 1. 产品定义

**一个轻量、可持久化的多窗格文件工作台：把常用目录留在眼前，在不同位置之间快速跳转，重新打开后接着工作。**

核心组合：Q-Dir 式多窗格 + 快速文件定位 + 工作区恢复。

主要用户：同时处理多个项目、多个目录和大量文件的开发者、科研人员及高频桌面用户。

### 1.1 需要解决的问题

| 问题 | 产品能力 | 用户获得的结果 |
|---|---|---|
| 多个资源管理器窗口反复切换 | 同屏多窗格 | 同时查看项目、下载、数据、输出目录 |
| 常用目录反复寻找 | 每个窗格设置固定根目录 | 一键回到自己的工作据点 |
| 找到文件后仍需多次导航 | 统一快速跳转入口 | 搜索后在指定窗格打开位置 |
| 重启后重新布置工作环境 | 自动恢复与命名工作区 | 保留目录、布局及浏览状态 |
| 后续需要远程目录和专业工具 | Provider 与命令扩展 | 增加能力时不重写窗格 |

### 1.2 当前决策与边界

| 项目 | 本文采用的方案 |
|---|---|
| 平台 | Windows 优先交付；Core 保持跨平台，Linux/macOS 后续验收 |
| 技术路线 | C# + .NET 10 + Avalonia 12 系列，独立轻量工程 |
| 代码复用 | Camelotia 作为 Provider 参考与候选复用来源；不预设整库 fork |
| 搜索 | Windows 可选接入 Everything；内置局部搜索始终可用 |
| 首版范围 | 浏览、打开、导航、固定目录、多窗格、工作区保存恢复 |
| 后续范围 | 基础文件操作、命令插件、远程 Provider、更复杂布局 |
| 暂缓 | 自建全盘索引、AI 语义搜索、任意 UI 插件、云账号同步 |

这些是用于推进开发的建议基线，不代表此前已经逐项确认。产品名称、首发平台与首版文件操作边界可独立调整。

## 2. 核心使用流程

1. 启动后恢复上次工作区；首次启动显示双窗格。
2. 将项目、下载或数据目录分别分配到窗格，并按需设为固定根目录。
3. 在窗格内浏览；通过统一跳转框查找目录或文件。
4. 将结果定位到当前窗格或指定窗格，使用默认应用打开文件。
5. 将当前组合保存为“科研”“开发”等命名工作区。
6. 下次启动或切换工作区时恢复布局及位置。

典型验收场景：四窗格分别显示项目、原始数据、下载和输出；从搜索结果定位到项目内的某份文件；一键返回项目根目录；退出重开后恢复四个位置。

## 3. 功能模块与优先级

P0：首个可用版本必需；P1：日常使用增强；P2：扩展阶段。

| 模块 | P0 | P1 | P2 |
|---|---|---|---|
| 窗格与布局 | 1/2/4 窗格预设、分隔条调整、明确活动窗格 | 3 窗格、窗格交换、临时最大化 | 自由拆分、6+ 窗格、独立窗口 |
| 目录浏览 | 列表、排序、多选、刷新、默认应用打开 | 缩略图、预览、窗格标签页 | 自定义列、专业文件元数据 |
| 导航 | 地址输入、面包屑、前进/后退、上级目录 | 导航历史筛选、更多快捷动作 | 跨 Provider 导航 |
| 固定目录 | 设置、替换、清除固定根目录；一键返回 | 限制导航范围模式 | 批量目录模板 |
| 快速定位 | 当前列表过滤、历史/固定目录跳转、Everything 适配、局部递归搜索 | 搜索结果复用、可配置排序 | 自有索引、内容/语义搜索 |
| 工作区 | 自动恢复、命名保存、切换、重命名、删除 | 导入导出、布局模板 | 跨设备同步 |
| 系统集成 | 默认应用打开、在资源管理器中显示、打开终端、复制路径 | 原生右键菜单、外部拖放、全局唤起/托盘 | 更深入 Shell 集成 |
| 文件操作 | 由外部文件管理器完成 | 新建、重命名、复制、移动、回收站删除 | 跨 Provider 传输、压缩包 |
| 扩展 | 内置能力通过接口注册 | 命令插件 | Provider 插件、受控 UI 扩展 |

### 3.1 窗格行为

- 每个窗格独立保存当前位置、历史、选中项、排序及滚动位置。
- 同一时刻只有一个活动窗格；键盘命令默认作用于它。
- 搜索选择目标窗格时，应显示目标，避免覆盖其他窗格的位置。
- 缩减窗格数量时暂存被隐藏窗格状态；恢复布局时复用。只有明确关闭才移除。
- 首版采用有限布局预设，避免过早实现复杂拖拽停靠系统。

### 3.2 固定根目录与范围限制

**固定根目录 PinnedRoot 是窗格的返回锚点。** 默认允许浏览其他位置，根目录不随导航改变，点击“返回固定目录”即可回去。

范围限制是独立的 P1 选项：启用后，地址输入、上级导航与搜索跳转均检查目标是否位于允许范围；越界时可改用其他窗格。它是交互约束，不是文件系统安全沙箱。

目录不存在、磁盘未连接或无权限时，保留原路径并展示错误与重试入口，不自动改到其他目录。

### 3.3 三种查找行为

| 行为 | 范围 | 实现与边界 |
|---|---|---|
| 当前列表过滤 | 当前目录已加载的直接子项 | 内存过滤；不递归 |
| 快速跳转 | 固定目录、历史、用户输入路径 | 本地记录匹配；无需索引服务 |
| 文件搜索 | 用户选定目录及子目录，或 Everything 已索引范围 | 显示搜索范围与来源；支持取消、结果上限及分批返回 |

统一入口可提供模式切换，但不能把三种范围混为一谈。选择目录结果默认在目标窗格导航；选择文件结果默认定位父目录并选中，另提供“直接打开”。

Everything 通过 SDK/IPC 连接，依赖其兼容客户端在后台运行。[3] 未安装、未启动或不兼容时，保留快速跳转和用户限定目录的递归搜索，明确提示全局搜索不可用。不能把局部搜索展示成全盘结果。

局部搜索默认不跟随目录符号链接或 junction，避免循环；权限错误跳过并汇总；不在启动时自动扫描全盘。Everything 接入先使用字面关键词模式，高级查询语法后续单独开放。

### 3.4 工作区保存语义

- 命名工作区保存自己的布局、窗格与浏览状态；切换时先保存当前工作区，再加载目标。
- 自动保存使用防抖和事务；正常退出主动提交，异常退出恢复到最近一次成功保存。
- 会话仅记录最后活动工作区、窗口位置及当前焦点，不再复制另一套工作区状态。
- 每个工作区包含稳定 ID 与 schemaVersion，支持后续迁移。
- 恢复滚动位置与选中项尽力而为；文件已变化时保留有效项。
- 不把远程密码或密钥写进工作区，后续只存凭据引用。

## 4. 界面与交互约束

主界面分为三个区域：顶部工作区切换与统一跳转入口；中央多窗格；底部轻量状态区。每个窗格保留导航栏、文件列表与必要状态。

- 文件内容占主要面积，减少装饰卡片、重复标签与常驻说明文本。
- 活动窗格有清晰但克制的边框或标题强调。
- 操作使用文件管理器常见语义；猫的意象用于品牌和图标，不替换目录、搜索等基础术语。
- 加载、空目录、无结果、无权限与离线必须有不同反馈。
- 图标和缩略图延迟加载；远程或慢磁盘不得阻塞其他窗格。
- 首版提供应用内快捷键：地址栏、快速跳转、前进/后退、返回固定目录、窗格切换。全局热键后续处理占用冲突与配置。
- 命令、工具栏和快捷键调用同一命令入口，避免出现三套逻辑。

## 5. 技术架构

### 5.1 技术选型

| 层次 | 选择 | 作用 |
|---|---|---|
| 运行时 | .NET 10 LTS + C# | 主应用与业务逻辑 |
| 桌面 UI | Avalonia 12 稳定版本 | 多窗格、列表和跨平台 UI |
| 状态与绑定 | MVVM；默认 CommunityToolkit.Mvvm | ViewModel、通知和命令 |
| 依赖管理 | Microsoft.Extensions.DependencyInjection | 在应用入口组装实现 |
| 日志 | Microsoft.Extensions.Logging | 错误、耗时、Provider 状态 |
| 持久化 | SQLite + Microsoft.Data.Sqlite | 工作区、偏好及历史 |
| 文件访问 | .NET 文件 API + Local Provider | 异步目录读取及元数据 |
| Windows 搜索 | Everything Adapter | 隔离 SDK 与 Windows 依赖 |
| 发布 | 自包含桌面包，先 Windows x64 | 首版减少用户环境配置 |

.NET 10 为 LTS；Avalonia 官方已提供 12 系列文档与发布版本。[1][2] 初始化工程时锁定经过验证的具体 SDK 和包版本，不使用浮动版本。若复用 Camelotia 的某段代码依赖 ReactiveUI，则评估迁移或局部适配成本，不同时引入两套全局状态体系。

首版不引入 Rust、独立索引服务或 Native AOT。性能测量证明存在瓶颈后，再决定是否替换局部实现。

### 5.2 工程模块

| 工程 | 职责 | 依赖边界 |
|---|---|---|
| Catena.App | Avalonia Views、ViewModels、命令绑定、组装入口 | 使用 Core，入口注册各实现 |
| Catena.Core | 工作区、窗格、导航、搜索编排与服务接口 | 不依赖 UI、数据库或 Windows SDK |
| Catena.Contracts | Location、FileEntry、Provider 与命令契约 | 小而稳定，不暴露 UI/数据库对象 |
| Catena.Storage.Local | 本地目录枚举、元数据、变更监听 | 实现文件 Provider |
| Catena.Platform.Windows | 默认应用、终端、资源管理器和后续 Shell | 实现平台服务接口 |
| Catena.Search.Everything | IPC 适配、查询、结果转换与可用性检测 | 实现搜索 Provider |
| Catena.Persistence | SQLite 读写、迁移、恢复 | 实现 Core 定义的存储接口 |
| Catena.Tests | 核心规则、集成与回归测试 | 不进入产品运行时 |

内置命令先按功能放在现有工程。只有外部插件实际进入开发时，再增加 PluginHost 与 SDK 打包；只有接入远程目录时，再增加相应 Provider 工程。

运行依赖方向：UI 调用 Core；Core 使用契约与接口；具体实现由入口注入。Provider 不访问控件，ViewModel 不直接调用 Windows SDK 或 SQL。

### 5.3 核心数据模型

| 对象 | 核心字段 | 规则 |
|---|---|---|
| Workspace | Id、Name、Layout、Panes、ActivePaneId、SchemaVersion | 完整工作环境的保存单位 |
| Pane | Id、Location、PinnedRoot、NavigationPolicy、History、ViewState | 独立导航与显示状态 |
| Location | ProviderId、Uri | 表示位置，不绑定 Windows 路径格式 |
| FileEntry | Location、Name、Kind、Size?、ModifiedAt?、Capabilities | 属性允许未知或延迟加载 |
| Layout | Preset、PaneOrder、SplitRatios | v1 支持预设；自由拆分时再演进为树 |
| ViewState | Sort、Filter、SelectedLocations、ScrollAnchor | 不保存实际控件对象 |
| SearchQuery | Text、Mode、Scope、Limit、RequestId | 搜索范围和请求身份明确 |
| SearchResult | Location、Kind、Source、DisplayMetadata | 可定位、可判定来源与能力 |

URI 示例：本地路径用 `file:///D:/Research`，UNC 用 `file://server/share/folder`；未来可用 `sftp://connection-id/home/user/project`。连接 ID 指向连接配置，不在 URI 中携带密码。

位置相等、父子关系和路径规范化由对应 Provider 判断。不得全局转小写、用字符串前缀判断目录范围，或直接拼接路径；须处理空格、中文、分隔符与文件系统大小写差异。

### 5.4 最小服务契约

| 接口 | 核心能力 | 首版实现 |
|---|---|---|
| ILocationProvider | 枚举、查询条目、父位置、规范化、能力判断 | LocalFileSystemProvider |
| ISearchProvider | 可用性、支持范围、可取消查询、分批结果 | Everything、限定目录搜索 |
| IPlatformActions | 打开文件、显示所在位置、打开终端、复制路径 | WindowsPlatformActions |
| IWorkspaceRepository | 读取、保存、删除、迁移 | SqliteWorkspaceRepository |
| ICommandRegistry | 注册、可执行性判断、执行 | 内置命令 |

异步接口接受 CancellationToken。枚举与查询返回可增量消费的结果；异常转换为稳定错误类型，如 NotFound、AccessDenied、Unavailable、Unsupported。

读取、搜索、监听和写入按能力暴露。后续新增写入接口，不要求只读 Provider 实现复制、删除等无效方法；UI 根据 Capabilities 决定按钮状态。

## 6. 关键工程规则

### 6.1 响应速度与状态一致性

- 大目录使用虚拟化列表、后台枚举、批量 UI 更新；元数据按需获取。
- 每次导航与搜索生成请求 ID；新请求取消旧请求，只接收仍匹配当前 ID 的结果。
- 文件监听仅覆盖活动目录并去重；窗口切换与目录离开后释放引用。
- FileSystemWatcher 作为变更提示；合并重复事件，溢出或恢复连接时重新枚举，不能仅靠事件保证完整性。
- 目录读取失败只影响对应窗格；一个搜索 Provider 失败不阻断其他来源。

### 6.2 状态与可恢复性

SQLite 保存工作区定义、版本化状态、导航历史和设置；首版不保存全盘文件索引。迁移前备份，保存使用事务；损坏或迁移失败时提供恢复入口，不静默覆盖原库。

日志记录操作类型、错误与耗时；默认不记录文件内容、搜索全文或完整敏感路径。远程凭据后续交给系统凭据存储。

### 6.3 文件操作进入 P1 的条件

文件操作由独立服务调度，统一处理源/目标验证、重名冲突、进度、取消和失败反馈。Windows 本地操作优先验证系统 Shell 文件操作接口的适配成本。

跨卷移动可能退化为复制后删除：只有复制确认成功才删除源；不承诺所有操作可回滚。删除默认进入回收站；不支持回收站时必须明确显示行为。取消后若存在部分结果，应展示实际状态。

跨窗格拖放必须明确复制/移动意图。基础传输完成并验证后，再扩展跨 Provider 传输。

| 项目 | 参考内容 | 使用方式 |

| [Camelotia](https://github.com/reactiveui/Camelotia) | Storage Provider、异步文件访问、跨平台组织 | 先读小模块；验证依赖和许可后再决定复用 |

Camelotia 官方定位是跨平台云文件管理样例。[5] 因此不能将其视为已经验证的完整产品底座，也不以依赖更新代替稳定性判断。

实际纳入代码时记录来源、提交版本、文件范围、许可证与本地修改。授权不清晰的模块不进入主工程。参考交互和复制源代码是两种不同决策。

## 8. 扩展路径

### 阶段一：内置命令

“打开终端”“复制相对路径”“用编辑器打开”统一注册为命令。命令接收明确上下文：活动窗格、当前位置和选择项；不直接操作 ViewModel。

### 阶段二：外部命令插件

提供插件清单：Id、Version、ApiVersion、EntryPoint、Dependencies、声明能力。支持加载、禁用与错误记录；首期允许重启后生效，不承诺热卸载。

只接收用户信任的插件。AssemblyLoadContext 可用于程序集加载隔离，但不提供安全隔离；恶意代码或进程级崩溃仍可影响宿主。[4] 如需承载不可信插件，应另行设计进程隔离及受控通信。

### 阶段三：Provider 插件

先以一个真实场景验证接口，例如只读 SFTP。明确连接生命周期、离线状态、凭据、分页与不支持操作，再开放 SDK。WSL、云盘等能力逐个接入。

### 阶段四：UI 扩展

仅在多个真实需求出现后开放有限位置，例如预览区或工具栏。不要向插件暴露整个窗口控件树。

## 9. 开发路径与交付门槛

按完成门槛推进，不以固定周数代替验证。每阶段都应有可运行构建。

| 阶段 | 开发内容 | 完成门槛 |
|---|---|---|
| M0 技术验证 | Avalonia 列表、Local Provider、Everything 连通、默认应用打开 | Windows 实机验证大目录滚动与搜索；记录依赖、性能和限制 |
| M1 浏览闭环 | 单窗格扩展双窗格、地址导航、历史、活动窗格、取消旧请求 | 两窗格独立浏览；连续跳转不串目录；无权限不崩溃 |
| M2 工作区闭环 | 1/2/4 布局、固定根目录、SQLite 保存、恢复和切换 | 完成四窗格典型场景；正常与异常退出恢复符合定义 |
| M3 搜索闭环 | 统一入口、Everything、限定目录搜索、目标窗格定位 | 有/无 Everything 均可用；范围准确；旧结果不覆盖新结果 |
| M4 P0 发布 | 快捷键、错误反馈、性能优化、安装/便携包、迁移 | 普通用户权限运行；真实目录回归通过；交付可用 MVP |
| M5 日常使用增强 | 基础文件操作、拖放、右键、命令插件、托盘 | 文件操作失败/取消场景通过；插件可禁用；主流程稳定 |
| M6 扩展 | 真实远程 Provider、Linux/macOS、更多布局 | 每个平台/Provider 独立验证后发布 |

推荐第一条开发任务：实现 `Location → Local Provider → 单窗格列表 → 默认应用打开` 的纵向闭环，然后扩展多窗格。不要先建立大量空接口和插件工程。

### 9.1 首批可执行任务

1. 建立解决方案、锁定依赖、Windows CI 编译与测试。
2. 定义 Location、FileEntry、Provider 契约与路径相等规则。
3. 实现本地目录增量读取与错误模型。
4. 实现虚拟化列表、地址导航及异步取消。
5. 建立独立 Pane 状态，验证双窗格互不干扰。
6. 实现固定根目录、有限布局与 SQLite 恢复。
7. 接入搜索编排、Everything 及限定目录降级方案。
8. 打包并在实际工作目录中试用，按测量结果优化。

## 10. 验收与性能目标

以下是待测目标，不是已实现指标。M0 固定基准机器、系统版本、Release 构建、目录数据集及测量脚本；记录 P50/P95，区分冷启动与缓存命中。

| 项目 | 建议目标/验收方式 |
|---|---|
| 可交互启动 | 本地有效路径、SSD、Windows x64：P95 ≤ 2 秒；慢磁盘不阻塞主窗口 |
| 本地首屏 | 10,000 条目目录，元数据延迟读取、默认渐进显示：P95 ≤ 300 ms；完整排序另测 |
| 快速跳转 | 本地历史与固定目录匹配 P95 ≤ 100 ms |
| Everything 搜索 | 索引就绪、返回上限 200 条，从提交到首批展示 P95 ≤ 200 ms |
| 大目录浏览 | 100,000 条目下窗口与滚动保持响应，不逐条触发 UI 重绘 |
| 空闲资源 | 四个本地窗格、无扫描无动画，60 秒平均进程 CPU < 1%；记录实际内存 |
| 工作区恢复 | 布局、当前位置、固定根目录正确；失效路径保留并允许重试 |
| 稳定性 | 连续导航、切换、断开磁盘、搜索取消，不串窗格、不覆盖新结果 |

必须覆盖的回归用例：中文/空格/长路径、UNC、大小写差异、无权限、目录删除、可移动盘离线、符号链接循环、监听溢出、配置迁移、Everything 不可用。

测试重点是路径语义、导航竞态、保存恢复和文件操作正确性。UI 使用少量关键流程自动化与 Windows 实机检查；不为简单样式写大量测试。

## 11. 后续决策触发条件

| 议题 | 何时决策 |
|---|---|
| 是否自建索引 | Everything 依赖明显阻碍用户使用，或跨平台全局搜索成为明确需求 |
| 是否引入 Rust | Profiler 证明 .NET 局部算法成为瓶颈，且优化与接口替换收益可量化 |
| 是否开放正式 SDK | 至少两个不同扩展验证现有契约可复用 |
| 是否升级自由布局 | 用户实际需要的布局超出预设，而不是仅为技术完整性 |
| 是否跨平台发布 | Windows 核心流程稳定，平台服务已解耦，目标平台有真实使用场景 |
| 是否增加 AI | 已有具体检索/整理任务，且传统查找不能有效满足 |
